- Pure `analysis.ts`, `fingerprint.ts`, `alignment.ts`, and `diff.ts` algorithms. Analysis waits for complete event reduction/tool input, retains chronological/parent/turn ordinals, normalizes structure, hashes canonical JSON with SHA256, and exposes status, duration, available usage/cost, output class and errors. Pure comparison uses timestamp zero; the store assigns creation time when persisting it.
- Turn-aware weighted sequence alignment: exact fingerprint score 12, same-operation substitution 2, matching parent context +1, gap penalty -4. Deterministic tie order favors diagonal, then missing, then inserted. Unique exact unmatched steps with the same parent context and outcome can become high-confidence reorders. Repeated matches are medium confidence; absent operation identity or still-running steps are low confidence. Explanations accompany every row.
- SQLite migration 3 adds rebuildable `run_steps` and `run_diffs`, a fingerprint index and unique directional pair/version index. Step rows also persist turn ordinal and fingerprint version. Comparison calculation and cache writes run in one `BEGIN IMMEDIATE` snapshot. Appends and annotations invalidate affected derived rows; delete/prune cascades; analyzer changes remove old derived rows and the next POST rebuilds. The schema needs a minimum 24-page physical floor (96 KiB) instead of 16; configured logical event-byte limits remain enforced. This is the same pre-existing minimum-page policy enlarged for the added tables.
- Shared secured `POST /api/diffs {badRunId,goodRunId}` and `GET /api/diffs/:id` in both Studios. Sides never swap. Missing or conflicting outcome labels produce a visible warning. Duplicate sides, unknown fields, bad IDs/query/media type and unsupported methods are rejected; missing runs or invalidated/version-obsolete IDs return 404. POST again to rebuild. Default durable SQLite implements the optional comparison methods; custom injected RunStore implementations must implement them to support this feature.

Failed → Compare with Worked opens a bounded, searchable, paginated Worked-only picker with label/provider/model/date. Other outcomes require an intentional picker choice and warning. Side-by-side chronological route cards, sticky side headings, change rail, paired selection and proportional linked scrolling, and one primary First divergence action show both relevant steps or an explicit missing-side placeholder. Original-event inspection exposes local evidence; all trace data is rendered with textContent. Closing returns to the existing viewer; selecting another run/baseline or mutating history closes the comparison. Stale responses cannot reopen a closed view. ## Exact scope and limits

Fingerprint/analyzer **V1 is PROVISIONAL**. There are **zero real developer pairs, zero human-reviewed pairs, and no release acceptance evidence**. The 24 cases are explicitly `synthetic_structural`, `humanReviewed: false`, with fabricated canonical traces and authored expectations; they do not imply live provider capture. See `fixtures/comparison/README.md` and `docs/brief-3-human-review.md`.

V1 intentionally collapses ordinary string/number/boolean literals and paths to types/extensions. It preserves selected decision fields, not every execution distinction. It is a conservative lexical shell/SQL summary, not a full shell or SQL parser: compound control operators, nested scripts, quoted SQL identifiers/CTEs, positional literals, two same-extension files, and changed answer prose can collide. Valid alternative routes and independent subagent scheduling can differ. Metadata, timing, cost and ordinary output text do not choose first divergence; status and coarse output-class changes do. Original evidence remains inspectable. The real corpus must identify which of these distinctions matter before freezing V1.

Alignment is chronological sequence alignment by ordinal user turn, not semantic turn matching, recursive branch alignment or graph isomorphism. Parent context is a tie signal, not proof of equivalence. Matrix allocation is capped at 4 million cells per turn (HTTP 422 for larger comparisons); the full selected runs are still read into memory and comparisons are synchronous within a write transaction. Large-run responsiveness/throughput is not benchmarked. Cache IDs are content/version-derived; an invalidated GET does not silently return stale results. Comparison is a snapshot; repeat the action for new incoming events. Confidence labels describe matching evidence, not statistically calibrated correctness or causality.

The pending human gate requires 20–30 real Worked/Failed pairs across Claude and Codex, blind expected alignments/first divergences, separate usefulness judgments, perturbation checks and an explicit human release decision. The prepared local recording/scoring workflow does not attest reviewer honesty, validate declared provenance, or grant release approval automatically. Stop here at comparison; do not proceed to Briefs 4–6.
